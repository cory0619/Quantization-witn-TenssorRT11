참조 코드의 ConvNeXt 활용 분석

대상: E:\forgeAI_practice\ForgeAIServer_v1.0.1\train_test_forgeai.py (+ pretrained_weights.py) · 환경: segmentation_models_pytorch 0.5.0, timm 1.0.24 · 작성 2026-10-17. 아래 수치는 모두 py310 환경에서 참조 코드의 build_model()을 그대로 만들어 실제로 잰 값이다 (검증 표시). 코드에 없는 설계 의도 해석은 추정으로 표시했다.

한 줄 결론
  • ConvNeXt-Base 는 DeepLabV3+ 의 encoder(특징 추출기)로만 쓰인다. smp 의 DeepLabV3Plus(encoder_name="tu-convnext_base") 가 timm 의 convnext_base 를 features_only=True 로 만들어 다단계 특징맵만 받는다.
  • ConvNeXt 의 ImageNet 분류 head(head.norm, head.fc) 는 버리고, 나머지 340 개 텐서 전부를 사전학습 파일에서 로드한다. 동결(freeze) 없이 encoder 전체를 디코더와 같은 학습률(Adam 5e-4)로 미세조정한다.
  • 디코더(ASPP + low-level 융합)와 세그멘테이션 헤드는 ConvNeXt 가 아니라 smp 의 DeepLabV3+ 구성요소다. ConvNeXt 가 내놓는 4 개 특징맵 중 실제로 디코더가 쓰는 것은 2 개(1/4 특징, 마지막 특징)다.
  • encoder 는 output_stride=16 으로 만들어져 마지막 stage 가 stride 대신 dilation 2 를 쓴다. 그래서 마지막 특징맵이 1/32 이 아니라 1/16 해상도다.
  • 새 모델(unet_model_convnext.py, R6)은 이 중 백본만 가져오고(같은 timm 모델, 같은 사전학습 파일, 같은 key 변환), ASPP 대신 R5 식 덧셈 skip 디코더와 full-res 가지를 붙였다.

2. tu-convnext_base 의 실체 검증

smp.encoders.get_encoder() 는 이름이 tu- 로 시작하면 TimmUniversalEncoder 를 만들고, 그 안에서 timm 모델을 이렇게 만든다 (segmentation_models_pytorch/encoders/timm_universal.py):

timm.create_model("convnext_base", in_chans=1, features_only=True, output_stride=16,
                  pretrained=False, out_indices=(0, 1, 2, 3))      # -> timm FeatureListNet
  • features_only=True: 분류 head 없이 각 stage 출력(특징맵 리스트)만 돌려주는 FeatureListNet. 최상위 Sequential 이 stem_0, stem_1, stages_0 … stages_3 으로 평탄화된다 (참조 코드 key 변환의 이유).
  • ConvNeXt 는 stride 4 의 patchify stem 으로 시작해 특징 축소율이 (4, 8, 16, 32) 다. smp 는 이를 "transformer-style" 로 분류해, 전통적 CNN 의 (2, 4, 8, 16, 32) 와 모양을 맞추려고 1/2 자리에 채널 0 짜리 더미 텐서를, 맨 앞에 입력 자체를 끼워 넣는다.
  • 그 결과 encoder.out_channels = [1, 0, 128, 256, 512, 1024], encoder(x) 는 길이 6 리스트 [x, dummy, f4, f8, f16, f32'].
  • output_stride=16 (DeepLabV3Plus 기본값): timm ConvNeXt 는 누적 stride 가 16 에 도달하면 다음 stage 의 downsample conv 를 stride 1 로 두고 dwconv 에 dilation 2 를 준다 (timm/models/convnext.py, if curr_stride >= output_stride and stride > 1: dilation *= stride). 그래서 stage 3 출력 f32' 는 1/32 가 아니라 1/16 이다 (feature_info.reduction() == [4, 8, 16, 16]).

ConvNeXt-Base 내부 (smp 가 만든 객체에서 확인한 값)

ConvNeXtBlock = depthwise Conv 7×7 → LayerNorm → Linear(C→4C) → GELU → Linear(4C→C) → LayerScale(gamma) → residual. encoder 안에 BatchNorm 은 0 개, LayerNorm 40 개, GELU 36 개. smp 가 drop_path_rate 를 넘기지 않아 stochastic depth 는 꺼져 있다 (drop_path = Identity).

5. 정리: ConvNeXt 가 "하는 일" 과 "하지 않는 일"

ConvNeXt 가 하는 일ConvNeXt 가 하지 않는 일 (smp DeepLabV3+ 또는 참조 코드 몫)
  • 입력 이미지에서 1/4, 1/8, 1/16, 1/16(dilated) 특징맵 4 장 추출
  • ImageNet-22k 사전학습 특징 제공 (학습 이미지가 적어도 수렴)
  • 미세조정으로 PCB/금형 도메인에 적응 (encoder 가중치도 갱신됨)
  • 클래스 예측 (head 1×1 conv) / 다중 스케일 문맥 (ASPP) / 저수준 융합 (block1, block2)
  • 해상도 복원 (bilinear ×4 ×2)
  • 손실 (sigmoid + MSE + Dice, 다중 라벨), 클래스 가중치, dropout hook, batch-1 BN 처리
  • ImageNet 분류 (head 버림), 입력 정규화 (참조 코드는 /255 만 하고 mean/std 정규화 없음)

참고: 참조 코드 주석은 "입력 크기가 output stride(32)의 배수여야 한다" 고 적었지만, smp 의 check_input_shape() 는 encoder.output_stride = min(16, 25) = 16 의 배수만 검사한다 (848, 1056 은 32 의 배수이기도 해서 실행에는 차이 없음).
