ConvNeXt 백본을 쓸 때(R6)와 안 쓸 때(R5): 구조 비교

대상: unet_model_int8_pruning_R5.py (UNet_8_dense_int8) 와 unet_model_convnext.py (UNet_ConvNeXt) · 작성 2026-10-17 · 수치는 두 모델을 py310 환경에서 실제로 만들어 잰 값 (검증). 해석은 추정 으로 표시.

이름 정리. R5 (unet_model_int8_pruning_R5.py) 에는 ConvNeXt 가 없다. 37,923 파라미터를 처음부터 학습하는 모델이고, hole IoU 0.60 이 나온 모델이다. ConvNeXt 를 쓰는 모델은 어제 만든 R6 (unet_model_convnext.py) 이고, 지금 학습 스크립트 unet_patterning_train_test_fp32_pcb.py 가 build_model() 로 만드는 모델이 R6 다. 이 문서는 두 모델을 같은 그림 위에 놓고 무엇이 같고 무엇이 바뀌었는지 설명한다.
한 줄 결론
  • 두 모델 모두 "인코더 ↓ → 디코더 ↑ + skip 덧셈" 의 UNet 이다. 디코더 부품(Up), 출력층(outc), 입출력 형식(uint8 BGR 입력, 비트 패킹 uint8 출력)은 같다.
  • 바뀐 것은 인코더 다. R5 는 stride-2 conv 두 개(down1, down2)로 1/4 까지만 내려가고 특징 채널이 64 다. R6 는 그 자리에 ConvNeXt-Base(36 블록, 1/32 까지, 1024 채널, ImageNet 사전학습 87.6M)를 넣었다.
  • 인코더가 깊어진 만큼 디코더도 Up 을 2 번에서 5 번으로 늘렸다. R6 의 마지막 두 Up(up4, up5) 과 inc, down1 은 R5 와 모양이 같다.
  • ConvNeXt 는 분류기(head) 없이 특징맵 4 장(f4, f8, f16, f32)을 뽑는 데만 쓰인다. R5 의 inc/down1 가지는 그대로 남아 ConvNeXt 에 없는 1/1, 1/2 해상도 skip 을 공급한다. 두 가지는 입력에서 병렬 로 갈라진다.
  • 이 구조 변화가 hole 에 중요한 이유: R5 는 출력 픽셀 하나가 입력의 13×13 px 만 본다(측정). hole 지름은 32~56 px 다. R6 는 입력 전체를 본다.

먼저: 용어 풀이

그림과 표에 나오는 말들을 쉬운 말로 풀고, 이 모델에서 실제로 어떤 숫자인지 붙였다. 입력은 1088×1344 BGR 컬러 한 장 기준.

용어쉬운 뜻이 모델에서
인코더 / 디코더인코더: 이미지를 점점 작게 줄이면서 "무엇이 어디 있는지" 를 요약하는 앞부분. 디코더: 그 요약을 다시 원래 크기로 키우면서 픽셀마다 답(pcb/terminal/hole)을 내는 뒷부분. R5 인코더 = inc, down1, down2. R6 인코더 = inc, down1 + ConvNeXt. 디코더는 둘 다 Up 들 + outc.
inc / outc / down / up원조 UNet 코드(milesial)에서 내려온 층 이름. inc = input conv, 맨 처음 입력 이미지를 받는 conv. outc = output conv, 맨 마지막에 답(logits)을 내는 conv. down = 줄이는 칸, up = 키우는 칸. inc = Conv3×3 (3→16 ch) + BN + ReLU. 해상도는 그대로, 픽셀마다 색 3 개를 특징 16 개로 바꾼다. (3, 1088, 1344) → (16, 1088, 1344), 파라미터 464. outc = Conv1×1 (16→3 ch). 픽셀마다 특징 16 개를 pcb/terminal/hole 점수 3 개로. 파라미터 51.
해상도 1/2, 1/4 … 1/32중간 결과의 가로·세로가 입력의 몇 분의 1인지. 줄일수록 한 칸이 입력의 넓은 범위를 대표한다. 1/1 = 1088×1344, 1/4 = 272×336, 1/32 = 34×42.
ch (채널)한 픽셀 자리에 들어 있는 숫자의 개수. 입력은 B, G, R 세 개. 깊이 들어갈수록 해상도는 줄고 채널은 늘어나 "그 자리에 무엇이 있는지" 를 더 많은 숫자로 적는다. 입력 3 ch → inc 16 ch → … → f4 는 픽셀마다 128 개, f32 는 1024 개.
특징맵, f4 / f8 / f16 / f32, x1 / s1 …어떤 층을 통과한 뒤의 중간 결과(텐서). f 뒤의 숫자는 해상도가 1/몇인지. x1, x2, s1, s2 는 코드의 변수 이름일 뿐이다. f4 = (128 ch, 272, 336). s1 = inc 출력 (16 ch, 1088, 1344).
Conv 3×3 / 1×1 / 4×4 / 7×7합성곱 필터의 크기. 3×3 은 주변 3×3 픽셀을 보고 값 하나를 만든다. 1×1 은 주변을 안 보고 그 자리의 채널들만 섞어 채널 수를 바꾼다. 클수록 한 번에 넓게 본다. R5 는 전부 3×3 (채널 맞춤용 1×1 포함). ConvNeXt 는 입구 4×4, 블록 안 7×7.
stride 2, ↓2, ↓4, 다운샘플필터를 한 칸씩이 아니라 두 칸씩 건너뛰며 적용해서 가로·세로를 절반으로 줄이는 것. ↓4 는 네 칸씩 건너뛰어 1/4 로. R5 down1, down2 = stride 2 인 3×3 conv. ConvNeXt 입구(stem) = stride 4 인 4×4 conv, 각 stage 앞 = stride 2 인 2×2 conv.
stem (줄기)네트워크 맨 앞에서 원본 이미지를 받아 첫 특징맵으로 바꾸는 입구 층. 식물의 줄기처럼 "모든 것이 여기서 시작" 이라는 뜻의 관용어. ConvNeXt stem = Conv 4×4 stride 4 (3→128 ch) + LayerNorm. 이미지를 4×4 픽셀 조각으로 잘라 조각 하나를 숫자 128 개로 바꾼다. (3, 1088, 1344) → (128, 272, 336).
block (블록)같은 모양으로 반복되는 작은 층 묶음, 레고 블록. 입력과 출력의 모양(해상도·채널)이 같아서 몇 개든 이어 붙일 수 있다. R5 의 블록 = Conv3×3 + BN + ReLU 한 묶음(ConvBlock). ConvNeXt 블록 = 7×7 depthwise conv → LayerNorm → Linear → GELU → Linear → ×gamma → 입력 더하기, 여섯 층짜리 묶음.
stage (단계)같은 해상도에서 작동하는 블록들의 묶음. stage 가 바뀔 때마다 해상도는 절반, 채널은 두 배가 된다. stage 0: 1/4, 128 ch, 블록 3 개 · stage 1: 1/8, 256, 3 개 · stage 2: 1/16, 512, 27 개 · stage 3: 1/32, 1024, 3 개.
"stem ↓4 + stage 0 (3 blocks)"위 셋을 합친 말. "입력을 stem 으로 1/4 로 줄여 128 채널로 만든 다음, 그 해상도 그대로 블록을 3 번 통과시킨다. 그 결과가 f4." R5 식으로 바꿔 말하면 "stride 4 로 줄이는 conv 하나 + 같은 해상도의 ConvBlock 세 개". 그림에서는 이제 "stem + stage 0 (1/4): 1/4 로 줄임 → 블록 3 개 → 128 ch" 로 적었다.
depthwise conv / dense convdepthwise: 채널마다 따로 필터를 돌리고 채널끼리는 섞지 않는다 (싸다). dense(보통 conv): 모든 입력 채널을 섞어서 출력 채널 하나를 만든다. R5 는 전부 dense. ConvNeXt 의 7×7 은 depthwise 이고, 채널 섞기는 바로 뒤의 Linear 두 개가 맡는다.
1×1 conv 로 채널 줄이기 (64 → 32)한 픽셀 자리에는 숫자 64 개(채널)가 있다. 1×1 conv 는 이 64 개를 가중치로 섞어 새 숫자 32 개를 만든다. 출력 채널 하나 = "64 개의 가중 합" 하나이고, 가중치는 32×64 행렬이다. 32 개를 버리는 게 아니라 64 개를 32 개의 조합으로 압축하는 것이다. 주변 픽셀은 보지 않으므로 가로·세로는 그대로다. 픽셀마다 같은 행렬을 쓰므로 nn.Linear(64, 32) 를 모든 픽셀에 적용한 것과 같다. 예: 한 픽셀의 입력이 [a, b, c, d] (4 ch) 이고 2 ch 로 줄인다면
out₁ = 0.5a + 0.1b − 0.3c + 0.2d
out₂ = −0.2a + 0.7b + 0.1c − 0.4d
이 8 개 계수가 학습되는 가중치. R5 up1 의 reduce 는 64→32 라 계수가 2,048 개.
concat (이어 붙이기) vs ⊕ 덧셈concat 은 두 이미지를 좌우로 붙이는 게 아니다. 가로·세로가 같은 두 특징맵을 채널 방향으로 쌓는 것이다 (torch.cat(dim=1)). 사진 32 장 묶음 두 개를 포개 64 장 묶음으로 만드는 셈이라 가로·세로는 그대로이고 두께만 2 배가 된다. 덧셈은 두께를 그대로 두고 같은 자리 값끼리 더한다 (32 장 + 32 장 → 32 장). 둘이 바꿔 쓸 수 있는 이유: conv 는 선형이라 "concat 뒤 1×1 conv (64→32)" 는 "a 에 1×1 conv + b 에 1×1 conv, 그 결과를 덧셈" 과 정확히 같은 계산이다 (가중치 행렬을 a 몫 32 열, b 몫 32 열로 쪼개면 된다). R6 up1~up3 = reduce(a) + lateral(b) 이므로 "concat → 1×1 conv" 와 완전히 동치. R5 와 R6 up4/up5 는 skip 쪽 1×1 을 항등(그대로)으로 고정한 특수한 경우. 원조 UNet 의 "concat → 3×3 conv (64→32)" 와 비교하면 3×3 공간 섞기를 합치기 전 에 각각 하느냐(원조) 후 에 한 번 하느냐(R5) 가 다르고, R5 쪽이 파라미터가 적다 (18,432 vs 2,048 + 9,216). TRT INT8 에서 concat 은 두 입력의 양자화 scale 이 달라 requantize 커널과 복사가 생기고, 덧셈은 앞 conv 커널에 융합되므로 R5 가 덧셈을 택했다.
Linear (= 1×1 conv)픽셀마다 채널 벡터에 행렬을 곱하는 것. 주변 픽셀은 보지 않고 채널만 섞는다. 이미지에서는 1×1 conv 와 같은 연산이다. ConvNeXt 블록 안에서 C → 4C → C 로 넓혔다 되돌린다. ONNX 에서는 MatMul 로 나타난다.
BatchNorm / LayerNorm값의 크기를 일정하게 맞춰 학습을 안정시키는 층. BatchNorm 은 배치 전체의 평균·분산으로, LayerNorm 은 픽셀 하나의 채널들 평균·분산으로 맞춘다. R5 는 BatchNorm (추론 때 conv 에 접혀 사라짐). ConvNeXt 는 LayerNorm 40 개 (추론 때도 남는다).
ReLU / GELU음수를 0 으로 자르는 비선형 함수 / 그것을 부드럽게 만든 버전. R5 ReLU, ConvNeXt GELU (ONNX 에서 Erf 로 보임).
잔차 연결 (residual)블록의 출력에 블록의 입력을 그대로 더해 주는 것. "바꿀 만큼만 바꾸고 나머지는 통과" 라서 수십 개를 쌓아도 학습이 된다. ConvNeXt 36 블록 전부 있음. R5 에는 없음.
gamma (layer scale) / drop pathgamma: 블록 출력에 곱하는 채널별 학습 계수 (처음엔 작게 시작). drop path: 학습 중 블록을 확률적으로 통째로 건너뛰는 과적합 억제. 추론 때는 없다. drop path 0.1. 둘 다 ConvNeXt 안에만 있다.
skip (⊕)인코더의 같은 해상도 특징을 디코더로 건너뛰어 더해 주는 연결. 줄였다 키우면서 잃어버린 "정확한 위치" 를 되돌려 준다. R5 2 개 (x1, x2), R6 5 개 (s1, s2, f4, f8, f16). 둘 다 이어 붙이기(concat)가 아니라 덧셈.
Up (nearest ×2 → 1×1 → ⊕ → 3×3)디코더 한 칸. 네 단계가 순서대로 한 번씩 일어난다. ① ×2: "두 번" 이 아니라 2 배 확대 한 번. 각 픽셀을 2×2 로 복제해 가로·세로를 2 배로 (파라미터 없음). ② 1×1: pointwise conv. 채널 수를 skip 과 같게 줄이기만 한다 (주변 픽셀 안 봄). ③ ⊕: 같은 크기가 된 skip 과 픽셀별 덧셈. ④ Conv3×3 + BN + ReLU: 덧셈 결과를 실제로 "학습해서 다듬는" 층. 이 블록에서 주변을 보는 유일한 층. R5 up1 = Up(64→32, skip x2): (64, 276, 340) → ×2 → (64, 552, 680) → 1×1 64→32 → (32, 552, 680) → + x2 (32, 552, 680) → Conv3×3 32→32 → (32, 552, 680). 파라미터 1×1 2,048 + 3×3 9,216 + BN 64 = 11,328. R6 up1~up5 도 같은 네 단계 (skip 채널이 다르면 skip 쪽에도 1×1 하나 더).
수용 영역 (receptive field)출력 픽셀 하나의 값에 영향을 줄 수 있는 입력 픽셀의 범위. 이 범위 밖은 그 픽셀이 "볼 수 없다". R5 13×13 px, R6 입력 전체.
사전학습 / 미세조정다른 큰 데이터(ImageNet, 1,400 만 장)로 먼저 학습해 둔 가중치에서 시작하는 것 / 그 가중치를 우리 데이터로 조금 더 학습하는 것. ConvNeXt 340 개 텐서 전부 사전학습에서 시작, lr 1e-4 로 미세조정. R5 는 전부 무작위에서 시작.
features_only / FeatureListNettimm 라이브러리가 분류 모델에서 분류기를 떼고, 각 stage 의 특징맵 리스트만 돌려주도록 포장한 형태. encoder(x) → [f4, f8, f16, f32]. 참조 코드의 tu-convnext_base 도 이것.
파라미터학습으로 정해지는 숫자(가중치)의 개수. 많을수록 표현력은 크지만 데이터가 적으면 외우기 쉽고, 사전학습이 그 위험을 줄인다. R5 37,923 개 · R6 88,833,955 개 (그중 87.6M 이 사전학습).

1. 구조 다이어그램 검증

왼쪽이 R5, 오른쪽이 R6. 가로줄 하나가 해상도 한 단계다 (1/1 이 입력 해상도). 같은 줄에 있는 상자는 같은 크기의 특징맵을 다룬다. 각 상자의 왼쪽 열은 인코더(내려가는 길), 오른쪽 열은 디코더(올라오는 길), 점선은 skip(덧셈)이다.

입출력 3×3 conv + BN + ReLU (R5 식) stride-2 다운샘플 conv (R5 식) ConvNeXt 백본 (사전학습, 7×7 depthwise + LayerNorm + GELU) Up: nearest ×2 → 1×1 → ⊕ skip → 3×3 conv skip (덧셈)

그림 읽는 법: 무엇이 같고 무엇이 다른가

같은 것 (R5 → R6 그대로)

  • 입력 형식: (B,3,H,W) BGR, 학습 때 0~1 float, 배포 때 uint8 ×1/255 를 모델 안에서.
  • inc (3→16), down1 (16→32, stride 2): 코드까지 동일한 ConvBlock.
  • Up 부품의 동작: nearest ×2 → 1×1 conv → skip 과 덧셈(concat 아님) → 3×3 conv + BN + ReLU. R6 의 up4/up5 는 R5 의 up1/up2 와 채널까지 같다.
  • outc 1×1 conv (16→3) 와 그 뒤의 sigmoid / 비트 패킹 / unpack_bits.

다른 것

  • 인코더 교체: R5 의 down2 (32→64, 1/4) 한 층 자리에 ConvNeXt-Base 4 단(1/4·1/8·1/16·1/32, 128·256·512·1024 ch)이 들어갔다. ConvNeXt 는 down1 의 출력이 아니라 정규화된 입력을 직접 받는다.
  • 디코더 연장: Up 2 번 → 5 번. 새로 생긴 up1~up3 은 skip 채널(512/256/128)이 출력 채널과 달라 skip 쪽에도 1×1 conv(lateral)가 붙는다.
  • 입력 정규화: ImageNet mean/std 를 BGR 순서로 모델 안에서 뺀다. 사전학습 가중치가 그 분포를 전제로 하기 때문이다.
  • 입력 크기 조건: 4 의 배수 → 32 의 배수 (1/32 까지 내려가므로). 그래서 학습 해상도가 1104×1360 → 1088×1344.
  • 학습 방식: ConvNeXt 는 사전학습 가중치에서 시작해 디코더(1e-3)보다 낮은 학습률(1e-4)로 미세조정하고 drop path 0.1 을 준다. R5 는 전부 무작위 초기화 단일 학습률.

2. R6 안에서 ConvNeXt 가 하는 일 (정확히)

  • 입력: 정규화된 이미지 (B,3,H,W) 한 장. inc 나 down1 의 출력이 아니다 (forward 의 f4, f8, f16, f32 = self.encoder(x)).
  • 출력: 특징맵 4 장. 1/4 128ch (f4), 1/8 256ch (f8), 1/16 512ch (f16), 1/32 1024ch (f32). timm features_only=True 로 만든 FeatureListNet 이라 ImageNet 분류기(head.norm, head.fc)는 애초에 모델에 없다.
  • 소비처: f32 는 up1 의 입력, f16/f8/f4 는 각각 up1/up2/up3 의 skip. 4 장 모두 쓴다 (참조 코드의 DeepLabV3+ 는 f4 와 마지막 특징 2 장만 썼다).
  • 가중치: 340 개 텐서 전부 timm/convnext_base.fb_in22k_ft_in1k 에서 로드. stem conv 만 RGB→BGR 입력 채널 순서를 바꿔 넣는다. 동결 없이 전부 학습된다 (encoder_parameters() 그룹, lr 1e-4).
  • 안 하는 일: 분류, 1/1·1/2 해상도 특징 생성 (stride-4 stem 이라 없음 → inc/down1 이 대신), 업샘플 (디코더 몫).
x  = (x - in_mean) * in_inv_std          # ImageNet 정규화 (BGR 순서 버퍼)
s1 = inc(x);  s2 = down1(s1)             # R5 와 같은 full-res 가지 (1/1, 1/2)
f4, f8, f16, f32 = encoder(x)            # ConvNeXt-Base: 4 장의 특징맵 (1/4 ~ 1/32)
y = up1(f32, f16)  → up2(y, f8)  → up3(y, f4)  → up4(y, s2)  → up5(y, s1)
logits = outc(y)                         # (B,3,H,W)   이후는 R5 와 동일

6. 왜 이 구조 변화가 hole 에 중요한가

6-1. 수용 영역 검증

출력 로짓 한 픽셀을 입력으로 미분해서 0 이 아닌 범위를 쟀다 (1088×1344 입력, 가운데 픽셀). 데이터셋 라벨 30 장의 hole 120 개 지름은 32~56 px (중앙값 54), 이미지 1358×1104 를 1344×1088 로 넣으므로 사실상 1:1 이다.

R5 는 다운샘플이 두 번(1/4)뿐이고 conv 가 전부 3×3 이라 수용 영역이 13 px 에서 끝난다. R6 는 ConvNeXt 가 1/32 까지 내려가고 그 위에서 7×7 depthwise conv 를 36 번 쌓으므로 f32 의 한 셀이 입력 전체를 본다. hole 안쪽 픽셀도 "원 전체가 보이는" 특징으로 판단할 수 있다. 추정 hole IoU 0.60 (R5) 의 상당 부분은 이 수용 영역 한계로 설명된다. terminal (183×257 px) 과 pcb (734×573 px) 는 질감·색만으로도 구분이 쉬워 R5 로도 0.88 / 0.95 가 나온 것과 맞는다.

6-2. 사전학습 추정

학습 이미지가 22 장이다. R5 의 37,923 파라미터는 전부 이 22 장에서 배워야 하지만, R6 의 특징 추출기 87.6M 은 ImageNet-22k(1,400 만 장)에서 배운 "모서리·원·질감" 특징을 가지고 시작하고 22 장으로는 그걸 PCB 에 맞게 조금만 옮긴다 (lr 1e-4). 2 epoch 만에 terminal IoU 0.81 이 나온 것이 그 효과다 (R5 는 같은 수준에 수백 epoch).

ONNX 연산 수는 3 절의 구조와 정확히 맞는다: MatMul 72 = 36 블록 × Linear 2, Erf 36 = 블록마다 GELU 1, LayerNormalization 40 = 블록 36 + stem 1 + 다운샘플 3, Transpose 80 = 블록마다 NCHW↔NHWC 왕복 2 (72) + LayerNorm2d 4 개의 왕복 (8), Conv 56 = depthwise 36 + stem 1 + 다운샘플 3 + 디코더/가지 16. R5 는 Conv 8 개가 전부다 (inc, down1, down2, up1 의 reduce·conv, up2 의 reduce·conv, outc).

TensorRT INT8 관점 추정: R5 설계의 요점은 "transpose·requantize 커널을 없앤다" 였는데, ConvNeXt 는 Transpose 80 개와 LayerNorm·GELU 를 다시 들여온다. TRT 는 LayerNorm/GELU 를 fp16 으로 융합해 처리하지만 INT8 양자화 대상은 Conv/MatMul 이고 블록마다 정밀도 전환이 생긴다. 기존 _1~_4 스크립트(batch 256 엔진)는 R6 에 맞지 않으며, R6 를 배포하려면 batch 와 프로파일을 다시 잡아야 한다.

8. 검증에 쓴 실행

  • struct_measure.py (scratchpad): 두 모델을 만들어 모듈별 파라미터, timm feature_info, stage/블록 구조(ConvNeXtBlock repr), 1104×1360 / 1088×1344 단계별 shape, torch.utils.flop_counter 로 FLOPs, 가운데 로짓의 입력 gradient 로 수용 영역을 쟀다. R5 수용 영역 (13, 13, 169 px), R6 (1088, 1344, 전체 픽셀).
  • R5 deploy 모델을 ONNX(opset 19) 로 내보내 R6 deploy ONNX(이전 export) 와 연산 종류를 셌다.
  • hole 지름: dataset_pcb 의 labelme JSON 30 장(백업 폴더 15 장 제외) 에서 circle 반지름 ×2.
  • 측정 중 GPU 에서 R6 학습(py310 python, 11.8 GB, 66%)이 돌고 있었다. 그래서 이번 fp16 속도 측정값(R5 20 ms, R6 1,254 ms/장)은 쓰지 않았고, R6 29 ms/장은 GPU 가 비어 있던 어제 측정값이다. 파라미터·shape·FLOPs·수용 영역·ONNX 수치는 GPU 부하와 무관하다.
