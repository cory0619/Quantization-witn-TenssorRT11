스케일 단위 3종

배치 원칙

가중 연산(Conv/GEMM) 입력은 양자화, 출력은 기본적으로 양자화하지 않음. 활성화는 per-tensor, 가중치는 per-channel.

최적화는 융합이 전부

TensorRT는 Q를 뒤로, DQ를 앞으로 밀어 저정밀 구간을 최대화하고, 양자화 가능 레이어를 DQ·Q와 묶어 하나의 양자화 커널로 바꿉니다.

1양자화란

양자화는 부동소수점 값을 더 낮은 정밀도의 자료형으로 표현해 모델 크기를 줄이고 연산을 빠르게 하는 기법입니다. 원문이 드는 이점은 네 가지입니다. 메모리 사용량 감소, 에너지 효율 향상, 자원이 제한된 엣지 기기에 배포 가능, 대규모 데이터센터에서의 비용 효율.

대칭(symmetric) 양자화

TensorRT는 활성화와 가중치 모두를 0을 중심으로 대칭인 양자화 값으로 매핑합니다. 비대칭 방식과 달리 영점 오프셋이 없어서, 양자화 표현과 부동소수점 표현 사이의 변환이 보통 스케일 계수 하나로 끝납니다.

2양자화 워크플로우: PTQ와 QAT

TensorRT는 학습 후 양자화(PTQ)와 양자화 인식 학습(QAT)을 모두 지원합니다. 스케일은 per-tensor, per-channel, 블록 단위 중 하나로 적용되며, 어느 방식을 쓰는지는 레이어와 자료형에 따라 다릅니다.

PTQ (Post-Training Quantization)QAT (Quantization-Aware Training)
방법이미 학습된 모델을 재학습 없이 양자화학습 중 가중치와 활성화를 양자화해 양자화 효과를 시뮬레이션
필요한 것양자화 파라미터를 계산할 대표 "캘리브레이션 데이터"레이블이 있는 전체 학습 데이터셋
장점재학습이 불가능한 경우(자원 제한, 데이터 프라이버시)에 실용적학습이 양자화/역양자화 오차를 능동적으로 보정해 PTQ보다 정확도 회복이 우수
단점복잡한 모델이나 민감한 레이어에서 정확도 저하 가능시간이 더 들고 전체 데이터 접근이 필요

TensorRT Model Optimizer는 QAT 모델을 만들기 위한 Python 툴킷으로, 결과 모델은 TensorRT 최적화·배포 워크플로우와 완전히 호환됩니다. PTQ 레시피도 제공하여 PyTorch 모델과 ONNX 모델 양쪽에 PTQ를 적용할 수 있습니다.

3Explicit vs Implicit 양자화

원문 NoteImplicit 양자화는 폐기(deprecated)되었습니다. Model Optimizer로 Explicit 양자화 모델을 만들어 전환할 것을 강력히 권고합니다.

양자화된 네트워크는 두 방식 중 하나(상호 배타적)로 처리됩니다. 차이는 "누가 양자화 위치를 정하는가"입니다.

  • Explicit: 네트워크에 IQuantizeLayer/IDequantizeLayer(이하 Q/DQ)가 있으면 이 모드. Q/DQ가 양자화·역양자화 지점을 명시적으로 제어합니다.
  • Implicit: Q/DQ가 없고 빌더 설정에 INT8과 weak typing이 켜져 있으면 이 모드. INT8만 지원하며, weak typing과 함께만 쓸 수 있고 둘 다 폐기되었습니다.

Implicit 모드의 동작

캘리브레이션 또는 setDynamicRange API로 스케일이 할당된 활성화 텐서가 양자화 후보가 됩니다. TensorRT는 그래프 최적화 시 모델을 부동소수점 모델로 다루고, 레이어 실행 시간을 줄일 수 있을 때만 "기회주의적으로" INT8을 씁니다. 어떤 레이어가 INT8에서 더 빠르고 입출력에 스케일이 있으면 INT8 커널, 아니면 고정밀(FP32/FP16/BF16) 커널이 배정됩니다.

Explicit 모드의 동작

Q/DQ 노드가 변환 위치를 정확히 지정하고, 옵티마이저는 모델 의미론이 요구하는 변환만 수행합니다. PyTorch나 TensorFlow 모델을 ONNX로 내보내면 프레임워크의 fake-quantization 연산이 Q 뒤에 DQ가 붙는 형태로 내보내지므로 ONNX는 본질적으로 Explicit 표현입니다. TensorRT는 이 레이어의 의미론을 보존하므로 프레임워크에서 본 정확도에 매우 근접한 결과를 기대할 수 있습니다. 단, 부동소수점 연산 순서가 바뀔 수 있어 비트 단위로 동일하지는 않습니다.

Explicit의 장점 (원문 4가지)

  • 넓은 자료형 지원: INT8, FP8, INT4, FP4.
  • 직접 제어: Q/DQ 노드로 변환 지점을 정밀하게 지정.
  • 모델 의미론 보존: 모델이 요구하는 변환만 수행하므로 원 프레임워크 정확도에 근접.
  • ONNX 내보내기와 자연스럽게 호환: 프레임워크에서 QAT/PTQ 후 ONNX로 내보내면 그대로 Explicit 모델.
중요Q/DQ 노드가 있는 모델에는 외부 캘리브레이션 테이블을 주면 안 됩니다. Q/DQ가 이미 있으면 TensorRT는 캘리브레이션 테이블 로드를 허용하지 않습니다. 즉 Explicit 모델의 캘리브레이션은 ONNX 내보내기 전(Model Optimizer의 PTQ/QAT 단계)에 끝나며, 결과 스케일은 Q/DQ 노드 안에 들어 있습니다.

Implicit 양자화와 weak typing은 본질적으로 묶여 있습니다. INT8으로의 변환 여부가 빌더 내부 휴리스틱에만 의존하므로 weak typing이 필요합니다. 둘 다 제어력이 떨어지고 자료형 범위가 좁아 폐기되었습니다. 일부 네트워크에서는 초기 Explicit 양자화가 Implicit보다 지연시간이 길 수 있는데, Model Optimizer 팀이 TensorRT 팀과 함께 이 격차를 줄이는 중이라고 원문은 밝힙니다.

4스케일 적용 단위 (Granularity)

Granularity는 스케일 계수를 텐서에 어떤 단위로 적용하느냐입니다. 세밀하게 나눌수록 정확도는 올라가지만 스케일을 관리하는 연산·메모리 비용도 늘어납니다. TensorRT는 세 가지를 지원합니다.

per-tensor

스칼라 하나로 텐서 전체를 스케일링합니다.

per-channel

스케일 텐서를 지정한 축을 따라 브로드캐스트합니다. CNN에서는 보통 채널 축입니다. Convolution에 per-channel을 쓸 때 양자화 축은 반드시 출력 채널 축이어야 합니다. 2D 컨볼루션 가중치를 KCRS로 표기하면 K가 출력 채널 축이고, 양자화는 다음과 같습니다.

For each k in K:
  For each c in C:
    For each r in R:
      For each s in S:
        output[k,c,r,s] := clamp(round(input[k,c,r,s] / scale[k]))

스케일은 양자화 축과 같은 길이의 벡터입니다. 역양자화는 점별 연산만 다릅니다.

output[k,c,r,s] := input[k,c,r,s] * scale[k]

블록(block) 양자화

요소를 블록으로 묶고, 한 블록 안의 모든 요소가 스케일 하나를 공유합니다. 입력은 최대 3차원까지 지원됩니다.

  • INT4 블록 양자화는 가중치 전용(WoQ)입니다.
  • FP4 블록 양자화는 가중치와 활성화 모두 지원합니다. 활성화는 양자화 오차를 줄이기 위해 동적 양자화(6장)를 권장합니다.

스케일 텐서의 차원은 블록을 나누는 축(blocking axis) 하나만 빼고 데이터 텐서와 같습니다. 2D 가중치 RS에서 R(차원 0)이 블록 축이고 블록 크기가 B이면:

For each r in R:
  For each s in S:
    output[r,s] = clamp(round(input[r,s] / scale[ceil(r//B), s]))

스케일은 (ceil(R//B), S) 모양의 2D 배열입니다. 역양자화는 output[r,s] = input[r,s] * scale[ceil(r//B), s].

5라운딩 모드

TensorRT는 주로 round-to-nearest-even("은행가 반올림")을 씁니다. 정확히 중간값이면 짝수로 반올림합니다(2.5 → 2, 3.5 → 4). 항상 올리거나 내리는 방식에서 생기는 체계적 편향(한쪽으로의 지속적 드리프트)을 줄여 줍니다.

백엔드연산 커널 양자화 (FP32 → INT8/FP8)가중치 양자화, Explicit가중치 양자화, Implicit (INT8만)
GPUties-to-eventies-to-even (INT8, FP8, INT4, FP4)ties-to-positive-infinity
DLAties-to-evenN/Aties-to-even

GPU에서 Implicit 모드의 가중치 양자화만 유일하게 +∞ 쪽 반올림(2.5 → 3)을 쓴다는 점이 예외입니다. 더 자세한 내용은 원문의 "Rounding" 장을 참조하라고 안내합니다.

6동적 양자화 (Dynamic Quantization)

스케일을 미리 정하지 않고 추론 중에 입력 데이터로부터 계산하는 방식입니다. 출력은 두 개, 양자화된 데이터와 스케일입니다. TensorRT는 블록 granularity에서만 동적 양자화를 지원합니다.

  • 정확도: 블록 하나의 동적 범위만 양자화 타입에 매핑합니다. 블록의 범위는 텐서 전체 범위보다 훨씬 좁은 경우가 많아 양자화 오차가 줄어듭니다. 표현 가능한 값이 몇 개 안 되는 서브바이트 타입(FP4 등)에서 특히 중요합니다.
  • PTQ 부담 감소: 스케일이 추론 중 자동 계산되므로 샘플 데이터로 스케일을 캘리브레이션할 필요가 없습니다.
블록별 스케일scale = maxi ∈ {0 … blockSize−1} ( |xi| / qTypeMax )
  • qTypeMax: 양자화 타입의 최댓값 (예: FP4E2M1은 6)

MX 호환 동적 양자화 (MXFP8)

OCP Microscaling Formats(MX) 사양 v1.0을 따르는 동적 양자화입니다. 고정밀 요소 32개를 묶어 양자화 값 32개와 E8M0 스케일 1개를 만듭니다. TensorRT는 현재 FP8E4M3 벡터 형식(MXFP8)에서만 지원합니다.

블록 하나의 스케일scaleE8M0 = round_up_to_e8m0( maxi ( |xi| / qTypeMax ) )
  • E8M0: 지수만 있는 8비트 부동소수점 타입
  • round_up_to_e8m0: 계산된 스케일보다 크거나 같은 가장 작은 2의 거듭제곱으로 올림
  • 블록마다 반복하여 총 inputVolume / blockSize 개의 스케일을 계산

동적 이중 양자화 (Dynamic Double Quantization, NVFP4)

계산된 스케일까지 다시 양자화하는 변형입니다. 현재 NVFP4 벡터 형식(FP4E2M1 데이터, FP8E4M3 스케일, 블록 크기 16)에서만 지원합니다.

스케일 계산 + 스케일 양자화scalequantized = quantize( maxi ( |xi| / qTypeMax ), scale = globalSf )
  • globalSf: 오프라인에서 캘리브레이션한 per-tensor 스케일(스칼라)
qTypeMax = 6, FP8 범위 [-448, 448]을 대입하면scalefp8 = castToFp8( maxi |xi| / (6 · globalSf) )

데이터는 이 스케일로 블록 양자화됩니다. 역양자화는 Dequantize를 두 번 연속으로 수행해야 합니다(그래서 "이중"). 먼저 per-tensor 스케일 globalSf로 스케일을 복원하고, 그 스케일로 데이터를 복원합니다.

dataDQ = dequantize( dataQ, dequantize( scaleQ, scale = globalSf ) )
x (hp, 블록 16)→ max|x| / 6→ ÷ globalSf→ castToFp8 → scale_fp8
x→ ÷ (scale_fp8 · globalSf)→ castToFp4 → data_fp4

원문 그림은 이 과정이 GEMM과 융합되는 예를 보여줍니다(hp = 고정밀, sf = 스케일 계수). 위 플로우는 수식을 단계로 풀어 쓴 것입니다.

7타입별 양자화 수식

모든 스킴의 역양자화는 동일하게 x = xq · s 입니다. 차이는 양자화 쪽의 클리핑 범위와 반올림/캐스팅 함수입니다.

INT8

xq = quantize(x, s) = roundWithTiesToEven( clip( x / s, −128, 127 ) )
x = dequantize(xq, s) = xq · s
  • x: 양자화할 고정밀 부동소수점 값 · xq: [-128, 127] 범위의 INT8 값
  • s: 16비트 또는 32비트 부동소수점 스칼라 스케일

Implicit 모드에서 TensorRT가 가중치 스케일을 계산하는 식:

s = max( |xchmin|, |xchmax| ) / 127

xchmin, xchmax는 가중치 텐서 채널 ch의 최솟값·최댓값.

FP8

xq = quantize(x, s) = castToFp8( clip( x / s, −448, 448 ) )
x = dequantize(xq, s) = xq · s
  • xq: [-448, 448] 범위의 FP8E4M3 값 · s: 16/32비트 부동소수점 스칼라
  • castToFp8: FP8E4M3에서 표현 가능한 가장 가까운 값으로 반올림, 중간값은 짝수로

MXFP8

동적 per-block 스킴. 출력 타입 FP8E4M3, 스케일 타입 E8M0, 블록 크기 32. 양자화·역양자화 수식은 FP8과 동일합니다. 활성화를 양자화할 때는 동적 양자화가 필수입니다.

INT4

xq = quantize(x, s) = roundWithTiesToEven( clip( x / s, −8, 7 ) )
x = dequantize(xq, s) = xq · s
  • xq: [-8, 7] 범위의 INT4 값 · s: 블록의 스케일(16/32비트 부동소수점)
  • per-block 스케일 필수. 지원 블록 크기 {64, 128}. 블록 축은 마지막 두 차원 중 하나
  • TensorRT는 INT4를 가중치 양자화에만 지원

NVFP4

xq = quantize(x, s) = castToFp4( clip( x / s, −6, 6 ) )
x = dequantize(xq, s) = xq · s
  • xq: [-6, 6] 범위의 FP4 값 · s: 블록의 스케일(16/32비트 부동소수점)
  • per-block 스케일 필수. 유일한 블록 크기 16. 블록 축은 마지막 두 차원 중 하나
  • castToFp4: FP4E2M1에서 표현 가능한 가장 가까운 값으로, 중간값은 짝수로
  • 활성화 양자화 시 동적 양자화 필수

8Explicit 양자화: 양자화된 가중치 저장

TensorRT가 네트워크에서 Q/DQ 레이어를 발견하면 Explicit 양자화 로직으로 엔진을 빌드합니다. Explicit 양자화는 Strong Typing과 Weak Typing 모두와 쓸 수 있고, 정밀도 제어 빌드 플래그는 필요하지 않으며 지정하지 말아야 합니다. weak typing이 폐기되었으므로 항상 strong typing을 쓰라고 권고합니다.

Q/DQ 모델의 가중치는 고정밀(FP32/FP16/BF16) 또는 저정밀 양자화 타입(INT8/FP8/INT4/FP4)으로 줄 수 있습니다.

  • 고정밀 가중치: 엔진 빌드 시 가중치에 걸린 IQuantizeLayer의 스케일로 양자화되고, 양자화된 저정밀 가중치가 엔진 플랜 파일에 저장됩니다.
  • 사전 양자화된 가중치: 가중치와 이를 쓰는 선형 연산 사이에 IDequantizeLayer가 필요합니다.

4비트 패킹

INT4와 FP4 가중치는 한 바이트에 두 요소를 담습니다. 첫 요소는 하위 4비트, 둘째 요소는 상위 4비트에 저장됩니다.

9ONNX 지원

PyTorch나 TensorFlow에서 QAT로 학습한 모델을 ONNX로 내보내면 fake-quantization 연산 하나가 QuantizeLinear + DequantizeLinear 쌍으로 나옵니다. TensorRT는 이를 각각 IQuantizeLayer, IDequantizeLayer로 임포트합니다.

원문 Warning · GEMM per-channel 축

ONNX GEMM은 per-channel 양자화가 가능한 연산자입니다. PyTorch torch.nn.Linear는 (K, C) 가중치 배치에 transB 속성이 켜진 GEMM으로 내보내지고(GEMM 전에 가중치를 전치), TensorFlow는 내보내기 전에 (C, K)로 미리 전치합니다.

  • PyTorch: y = xWT → TensorRT가 가중치를 전치. 양자화는 전치 전에 수행되므로 per-channel 축은 차원 0 (K = 0)
  • TensorFlow: y = xW → per-channel 축은 차원 1 (K = 1)

지원하지 않는 ONNX 양자화 연산자

INT8/FP8 양자화 연산자를 직접 쓰는 사전 양자화 ONNX 모델은 지원하지 않습니다. 다음 연산자를 만나면 임포트 오류가 발생합니다.

  • QLinearConv, QLinearMatmul
  • ConvInteger, MatmulInteger

10TensorRT의 Q/DQ 네트워크 처리

Q/DQ 모드에서 최적화는 네트워크의 산술적 정확성을 바꾸지 않는 범위로 제한됩니다. 다만 비트 단위 동일성은 거의 불가능합니다. 부동소수점 연산 순서가 바뀌면 결과가 달라지는데, 예컨대 a·s + b·s를 (a+b)·s로 다시 쓰는 것은 유효한 최적화입니다. 이런 차이를 허용하는 것이 백엔드 최적화의 근본이고, Q/DQ 그래프를 양자화 연산으로 바꾸는 데도 그대로 적용됩니다.

양자화 가능 레이어와 Q/DQ 융합

Q/DQ 레이어는 네트워크의 연산 정밀도와 데이터 정밀도를 제어합니다. Q는 고정밀 텐서를 양자화 텐서로, DQ는 그 반대로 바꿉니다. TensorRT는 양자화 가능 레이어(quantizable layer)의 각 입력마다 Q/DQ 쌍이 있을 것을 기대합니다. 양자화 가능 레이어란 Q/DQ와 융합해 양자화 레이어로 바꿀 수 있는 딥러닝 레이어입니다. 융합이 일어나면 그 레이어는 양자화 데이터를 양자화 타입용 연산으로 처리하는 양자화 레이어로 대체됩니다.

Q/DQ 전파 (propagation)

최적화 중 TensorRT는 Q/DQ 레이어를 이동시킵니다. 목표는 저정밀로 처리되는 그래프 비율을 최대화하는 것입니다. 이를 위해 Q는 뒤쪽(backward)으로 보내 양자화가 가능한 한 일찍 일어나게 하고, DQ는 앞쪽(forward)으로 보내 역양자화가 가능한 한 늦게 일어나게 합니다. Q는 양자화와 교환 가능한(commute) 레이어와, DQ는 역양자화와 교환 가능한 레이어와 자리를 바꿀 수 있습니다.

교환 가능(commute)의 정의Q( Op(x) ) == Op( Q(x) ) 이면 Op는 양자화와 교환 가능
Op( DQ(x) ) == DQ( Op(x) ) 이면 Op는 역양자화와 교환 가능

왜 MaxPool은 교환 가능한가 (원문 증명 스케치)

Max Pooling은 입력 계수 그룹에서 최댓값을 출력합니다. 그룹 i가 {x0 … xm}일 때 outputi = max({x0, x1, … xm}) 인데, 이는 max를 두 개씩 중첩 적용한 것과 같으므로 일반성을 잃지 않고 두 계수만 보면 됩니다.

xj ≥ xk 라고 하자. 양자화 함수 Q(a, scale, xmax, xmin) := truncate(round(a / scale), xmax, xmin), scale > 0 Q(xj, scale) ≥ Q(xk, scale) (단조성, 원문은 증명 생략)
⇒ max({ Q(xj), Q(xk) }) = Q(xj)
정의상 Q( max({xj, xk}) ) = Q(xj)
∴ max는 양자화와 교환 가능하고, Max Pooling도 그렇다.
역양자화 DQ(a, scale) := a · scale, scale > 0 에 대해서도 마찬가지로max({ DQ(xj), DQ(xk) }) = DQ(xj) = DQ( max({xj, xk}) )
양자화 가능 레이어 vs 교환 가능 레이어둘 다 INT8/FP8로 계산될 수 있지만 처리 방식이 다릅니다. 양자화 가능 레이어는 입력 DQ·출력 Q와 융합됩니다(AveragePool은 Q, DQ 어느 쪽과도 교환 가능하지 않으므로 이 경로). 교환 가능 레이어는 Q/DQ가 그 레이어를 통과해 지나갑니다(MaxPool).

11Weight-Only 양자화 (WoQ)

GEMM 성능이 메모리 대역폭에 묶여 있거나 GPU 메모리가 부족할 때 유용한 최적화입니다. GEMM 가중치만 INT4로 양자화하고, 입력 데이터와 연산은 고정밀을 유지합니다. TensorRT의 WoQ 커널은 4비트 가중치를 메모리에서 읽어 역양자화한 뒤 고정밀로 내적을 수행합니다.

INT4 weights (메모리)→ dequantize→ fp GEMM (고정밀) ← fpinput (FP32/FP16/BF16)

WoQ는 INT4 블록 양자화 + GEMM 레이어 조합에서만 가능합니다. 가중치는 평소처럼 Q/DQ로 양자화하고, 데이터 입력은 고정밀로 지정하면 TensorRT가 INT4 가중치 + 고정밀 GEMM 엔진을 만듭니다.

12Q/DQ 배치 권고

Q/DQ를 어디에 두느냐가 성능과 정확도를 결정합니다. 공격적으로 양자화하면 오차 때문에 정확도가 떨어지지만 지연시간은 줄어듭니다. 원문의 권고를 순서대로 정리합니다.

빌드 오류 시오래된 기기에는 모든 레이어의 저정밀 커널이 없을 수 있어 엔진 빌드 중 could not find any implementation 오류가 날 수 있습니다. 실패한 레이어를 양자화하는 Q/DQ 노드를 제거하면 해결됩니다.

권고 1. 가중 연산의 모든 입력을 양자화

Convolution, Transposed Convolution, GEMM의 입력(가중치와 활성화)을 양자화하면 대역폭 요구가 줄고 INT8 연산으로 대역폭 제한·연산 제한 레이어 모두 가속됩니다. 원문 그림은 입력만 양자화한 경우와 입력·출력 모두 양자화한 경우 두 가지 Conv 융합 예를 보여줍니다.

권고 2. 가중 연산의 출력은 기본적으로 양자화하지 않음

역양자화된 고정밀 출력을 유지하는 것이 유용한 경우가 있습니다. 예를 들어 선형 연산 뒤에 활성화 함수(원문 예시는 SiLU)가 오면, 수용 가능한 정확도를 내기 위해 고정밀 입력이 필요합니다.

권고 3. BN·ReLU 융합을 학습 프레임워크에서 흉내 내지 말 것

TensorRT 최적화가 이 연산들의 산술 의미론 보존을 보장합니다. Batch Normalization은 융합 전 네트워크의 실행 순서를 유지한 채 Convolution·ReLU와 융합되므로, 학습 네트워크에서 BN 폴딩을 시뮬레이션할 필요가 없습니다.

권고 4. 스킵 연결의 잔차(residual) 입력을 양자화

TensorRT는 가중 레이어 뒤의 element-wise 덧셈을 융합할 수 있어 ResNet, EfficientNet 같은 스킵 연결 모델에 유용합니다. 핵심 규칙은 element-wise 덧셈의 첫 입력 정밀도가 융합 출력의 정밀도를 결정한다는 것입니다.

권고 5. 추가 성능이 필요하면 교환 불가능한 레이어도 양자화 시도

현재 가중치 없는(non-weighted) 레이어는 입력이 INT8이면 출력도 INT8이어야 하므로, 입력과 출력을 모두 양자화해야 합니다. 원문 그림은 element-wise 덧셈이 입력 DQ들과 출력 Q와 융합되는 예입니다.

권고 6. Q/DQ 추가는 보수적으로

주변 Q/DQ와 융합할 수 없으면 성능이 떨어질 수 있습니다. 정확도와 TensorRT 성능을 함께 보며 실험하십시오. 원문 그림은 Q/DQ 쌍이 추가로 끼어들어 Convolution이 element-wise 덧셈과 따로 융합되는 비최적(suboptimal) 융합 사례를 보여줍니다.

Conv→Q→DQ→Add→Q   비최적: Conv와 Add 사이의 Q/DQ 쌍이 둘을 갈라놓음
Conv→Add→Q   최적: 하나로 융합

권고 7. 활성화는 per-tensor, 가중치는 per-channel

이 조합이 경험적으로 가장 좋은 양자화 정확도를 냅니다. 추가로 FP16을 켜면 엔진 지연시간을 더 줄일 수 있습니다. TensorRT는 가능할 때마다 FP32 대신 FP16을 쓰려고 시도합니다(모든 레이어 타입에서 지원되는 것은 아님).

13Q/DQ 제약과 플러그인

Refit 시 스케일 동등성 제약

TensorRT의 일부 Q/DQ 그래프 재작성 최적화는 둘 이상의 Q/DQ 레이어 스케일 값을 비교해 같을 때만 재작성을 수행합니다. refit 가능한 엔진을 refit하면 Q/DQ 노드의 스케일에 새 값을 넣을 수 있는데, 스케일 의존 최적화에 참여한 Q/DQ에 재작성을 깨는 새 값이 들어오면 TensorRT는 예외를 던지고 refit을 중단합니다. 원문 그림: Q1과 Q2의 스케일이 같으면 후방 전파를 허용하는데, refit으로 Q1 ≠ Q2가 되면 예외.

플러그인과 Q/DQ

플러그인은 레이어 그룹을 커스텀 구현으로 대체합니다. 플러그인이 양자화 입력(INT8/FP8)을 받아 양자화 출력을 낼 때는 입력 DQ와 출력 Q를 플러그인 안으로 넣고 네트워크에서는 제거해야 합니다.

원문 예: 두 Conv 사이에 INT8 플러그인 MyInt8Plugin이 끼어 있는 순차 그래프(가중치 양자화는 무시). 파란 화살표는 FP32, 녹색 화살표는 INT8 텐서입니다. 대괄호는 TensorRT 융합.

Input>Q→DQ>Conv>Q→DQ_i>MyInt8Plugin>Q_o→DQ>Conv>Output

① 원래 그래프. 그대로 최적화하면 아래처럼 융합되고, 플러그인은 FP32 입출력을 받습니다.

Input>Q→DQ→Conv→Q→DQ_i>MyInt8Plugin>Q_o→DQ→Conv>Output

② 자동 융합 결과. 플러그인이 INT8을 쓰려면 DQ_i와 Q_o를 플러그인에 수동 통합하고, 그 플러그인 레이어에 setOutputType(kINT8)을 호출해야 합니다. 그러면 TensorRT는 네트워크를 다음과 같이 해석합니다.

Input>Q→DQ>Conv>Q→MyInt8Plugin→DQ>Conv>Output

③ DQ_i·Q_o가 플러그인 안으로 들어간 그래프. 최종 융합은 아래.

Input>Q→DQ→Conv→Q→MyInt8Plugin→DQ→Conv>Output

④ 플러그인 앞뒤가 모두 INT8 텐서가 됨. DQ_i를 "수동 융합"할 때는 입력 양자화 스케일을 플러그인에 넘겨 (필요하면) 입력을 역양자화할 수 있게 하고, Q_o의 스케일로 플러그인 출력을 양자화합니다.

14QAT 프레임워크 메모

TensorFlow
TensorRT Model Optimizer로 TensorFlow 2 Keras 모델에 NVIDIA QAT 레시피를 적용할 수 있습니다. TensorFlow 1은 per-channel 양자화(PCQ)를 지원하지 않는데, PCQ는 가중치 정확도 보존을 위해 권장되는 방식입니다.
PyTorch
PyTorch 1.8.0 이상은 ONNX QuantizeLinear/DequantizeLinear의 per-channel 스케일을 지원합니다. Model Optimizer로 INT8 캘리브레이션, QAT·PTQ(TensorRT가 지원하는 여러 정밀도), ONNX 내보내기를 할 수 있습니다.

15Implicit 양자화 (폐기)

원문 Note이 장은 Implicit 양자화에서만 쓸 수 있는 기능을 다루며 INT8에 한정됩니다. Implicit 양자화와 아래 API들은 폐기되었고 사용이 권장되지 않습니다. Explicit 양자화를 쓰십시오.

동적 범위 직접 설정 (Dynamic Range API)

TensorRT 바깥에서 계산한 값으로 텐서의 동적 범위(양자화 텐서가 표현해야 하는 범위)를 직접 지정하는 API입니다. INT8에만 적용됩니다. 최소·최대값을 주면 TensorRT는 대칭 범위만 지원하므로 스케일을 max(abs(min_float), abs(max_float))로 계산합니다. 따라서 abs(min_float) != abs(max_float)이면 설정한 것보다 넓은 범위가 쓰여 반올림 오차가 커질 수 있습니다.

// C++
tensor->setDynamicRange(min_float, max_float);

# Python
tensor.dynamic_range = (min_float, max_float)

C++ 사용 예는 sampleINT8API 샘플에 있습니다.

캘리브레이션을 이용한 PTQ

TensorRT가 네트워크의 각 텐서에 대해 스케일을 계산하는 과정이 캘리브레이션입니다. 대표 입력 데이터를 주면 네트워크를 실행하며 활성화 텐서별 통계를 수집합니다. 필요한 데이터 양은 응용에 따라 다르지만, ImageNet 분류 네트워크는 약 500장이면 충분하다는 실험 결과가 있습니다.

통계가 있어도 최적 스케일을 정하는 것은 정밀과학이 아닙니다. 두 오차의 균형이 필요합니다.

  • 이산화 오차(discretization error): 양자화 값 하나가 담당하는 범위가 넓어질수록 증가
  • 절단 오차(truncation error): 표현 범위 한계로 값이 잘릴 때 발생

그래서 TensorRT는 스케일을 다르게 계산하는 여러 캘리브레이터를 제공합니다. 오래된 캘리브레이터는 캘리브레이션 전에 GPU용 레이어 융합을 수행해 불필요한 텐서를 제거했는데, DLA는 융합 패턴이 달라 문제가 될 수 있으며 kCALIBRATE_BEFORE_FUSION 양자화 플래그로 덮어쓸 수 있습니다.

배치 크기와 히스토그램

IInt8EntropyCalibrator2와 IInt8EntropyCalibrator는 배치 크기가 절단 오차에 영향을 줍니다. 각 캘리브레이션 스텝마다 활성화 텐서별 히스토그램을 갱신하는데, 현재 최댓값보다 큰 값이 나오면 히스토그램 범위를 2의 거듭제곱 단위로 늘립니다. 마지막 스텝에서 재할당이 일어나면 빈(bin)의 절반이 비어 있는 히스토그램이 되어 스케일이 나빠집니다. 배치 순서에도 민감해져 순서가 다르면 스케일이 조금씩 달라집니다.

대책: 가능한 한 큰 단일 배치로 캘리브레이션하고, 배치를 잘 섞어 분포가 비슷하게 유지하십시오.

INT8 엔진 빌드 3단계와 캐시

  1. 32비트 엔진을 빌드해 캘리브레이션 세트로 실행하고, 텐서별 활성화 값 분포 히스토그램을 기록
  2. 히스토그램으로부터 텐서별 스케일을 담은 캘리브레이션 테이블을 생성
  3. 캘리브레이션 테이블과 네트워크 정의로 INT8 엔진 빌드

캘리브레이션은 느릴 수 있으므로 2단계 결과(테이블)를 캐시해 재사용할 수 있습니다. 모든 캘리브레이터가 지원합니다. 캘리브레이션 전에 TensorRT는 캘리브레이터에 캐시된 테이블이 있는지 묻고, 있으면 3단계로 바로 갑니다. 캐시 데이터는 포인터와 길이로 전달됩니다.

  • 기기 간 이식성: 캘리브레이션이 레이어 융합 전에 일어나면 캐시는 다른 기기에서도 쓸 수 있습니다. 즉 IInt8EntropyCalibrator2, IInt8MinMaxCalibrator, 또는 QuantizationFlag::kCALIBRATE_BEFORE_FUSION 설정 시. 예: 데스크톱 GPU에서 테이블을 만들어 임베디드 플랫폼에서 재사용. 융합은 플랫폼·기기 간에 동일함이 보장되지 않으므로 융합 후 캘리브레이션은 이식 불가.
  • TensorRT 릴리스 간에는 일반적으로 이식되지 않습니다.

TensorRT는 가중치 텐서의 최대 절댓값으로 스케일을 계산하는 대칭 양자화를 쓰고, convolution·deconvolution·fully connected 가중치는 per-channel 스케일입니다.

원문 Note · INT8 I/O빌더가 INT8 I/O를 쓰도록 설정되어도 캘리브레이션 데이터는 FP32여야 합니다. INT8 I/O를 FP32로 캐스팅해 만들 수 있으며, 이 데이터는 [-128.0, 127.0] 범위에 있어야 하고 정밀도 손실 없이 INT8로 변환되어야 합니다.

INT8 캘리브레이션은 동적 범위 API와 함께 쓸 수 있습니다. 수동으로 설정한 동적 범위가 캘리브레이션 결과를 덮어씁니다.

원문 Note · 결정성같은 기기에서 같은 입력을 같은 순서로 주면 생성되는 스케일은 실행마다 동일합니다. 같은 기기·같은 배치 크기·같은 입력이면 캐시 데이터도 비트 단위로 동일합니다. 기기, 배치 크기, 입력이 다르면 비트 단위 동일성은 보장되지 않습니다.

C++로 캘리브레이션

IInt8Calibrator 인터페이스를 구현해 캘리브레이션 데이터를 제공합니다.

  1. 입력 배치 크기를 정하고, 빌더가 getBatchSize()로 기대 배치 크기를 조회할 수 있게 합니다.
  2. getBatch()를 반복 호출해 배치를 공급합니다. 각 배치는 getBatchSize()와 정확히 같아야 하고, 데이터가 끝나면 false를 반환합니다.
  3. 빌더 설정에 연결: config->setInt8Calibrator(calibrator.get());
  4. 캐시 메서드 구현: writeCalibrationCache()(저장), readCalibrationCache()(있으면 읽기).

Python으로 캘리브레이션

import tensorrt as trt

# 검증셋처럼 전체 추론 데이터를 대표하는 파일들로 batchstream을 만든다
NUM_IMAGES_PER_BATCH = 5
batchstream = ImageBatchStream(NUM_IMAGES_PER_BATCH, calibration_files)

# 입력 노드 이름과 batchstream으로 캘리브레이터 생성
Int8_calibrator = EntropyCalibrator(["input_node_name"], batchstream)

# INT8 모드와 캘리브레이터 설정
config.set_flag(trt.BuilderFlag.INT8)
config.int8_calibrator = Int8_calibrator

양자화 노이즈 감소 휴리스틱

Implicit 양자화 네트워크에서 TensorRT는 출력 근처 일부 레이어를 INT8 구현이 있어도 FP32로 강제해 출력의 양자화 노이즈를 줄이려 합니다. 여러 양자화 값을 합산하는 "평활(smoothing) 레이어"(convolution, deconvolution, fully connected, matrix multiplication)가 출력 전에 있을 때 적용됩니다. 예: (convolution + activation + shuffle) 서브그래프가 반복되고 출력 타입이 FP32이면, INT8이 허용되고 더 빨라도 마지막 convolution은 FP32를 출력합니다.

다음 경우에는 적용되지 않습니다.

  • 네트워크 출력 타입이 INT8
  • 마지막 평활 레이어에서 출력까지의 경로(양 끝 포함)에 ILayer::setOutputType 또는 ILayer::setPrecision으로 INT8 출력이 강제된 연산이 있음
  • 출력으로 가는 경로에 평활 레이어가 없거나, 그 경로에 플러그인 레이어가 끼어 있음
  • 네트워크가 Explicit 양자화를 사용

부록. 프로젝트 적용 메모

원문 외 · 정리자의 추론

아래는 이 문서를 현재 파이프라인(FP32 학습 → ONNX → Model Optimizer INT8 PTQ → TensorRT 엔진)에 대응시킨 메모입니다. 원문 내용이 아니며, 엔진 로그와 ONNX 그래프로 확인이 필요합니다.

  • 해당 모드는 Explicit. Model Optimizer가 Q/DQ를 ONNX에 넣으므로 15장(캘리브레이터, 동적 범위 API, 노이즈 감소 휴리스틱)은 적용되지 않습니다. 3장의 경고대로 TensorRT 빌드 시 캘리브레이션 테이블을 따로 주면 안 됩니다. 스케일 결정은 ModelOpt 단계에서 끝납니다.
  • granularity 확인. 권고 7은 활성화 per-tensor, 가중치 per-channel입니다. ONNX의 가중치 쪽 DequantizeLinear 스케일 모양(스칼라인지 길이 K 벡터인지)과 axis 속성으로 ModelOpt가 실제로 어떻게 내보냈는지 확인할 수 있습니다. 9장 경고대로 PyTorch 출신 GEMM은 axis 0이어야 합니다.
  • Conv 출력 → GELU 경로. 권고 2(가중 연산 출력은 양자화하지 않음, 활성화 함수 앞은 고정밀)는 현재 엔진에서 Conv/MatMul은 INT8, LN/GELU는 FP16으로 남는 패턴과 일치합니다. 의도된 배치로 보입니다.
  • ConvNeXt 잔차 덧셈. 권고 4에 따라 스킵 입력에 Q/DQ가 없으면 Conv + Add 융합 출력이 FP로 제한되어 뒤의 Q가 Conv에 융합되지 못합니다. 엔진 레이어 정보에서 Add 주변 융합 여부를 보면 추가 Q/DQ 삽입 실험의 근거가 됩니다. 단, 권고 6의 비최적 융합 위험도 함께 봐야 합니다.
  • 빌드 플래그. 8장: Explicit 모델에는 정밀도 제어 빌드 플래그가 필요 없고 지정하지 말라고 되어 있으며 strong typing을 권장합니다. 현재 빌드 스크립트의 플래그 설정과 대조해 볼 가치가 있습니다.
  • 문서 버전. 이 원문은 TensorRT 10.x 문서이고 아카이브 상태입니다. 현재 사용 중인 TensorRT 11.x와 세부 동작(지원 opset, 융합 패턴, 플래그)이 다를 수 있으므로 결정에 쓰기 전에 현행 문서로 재확인이 필요합니다.
